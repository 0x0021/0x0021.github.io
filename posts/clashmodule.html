ClashModule：把散落的 Loon / Quantumult X 模块收拢成可一键导入 Clash 的索引

代理 工具 Clash Loon Quantumult X

可莉插件中心（Kelee Loon）的模块、Quantumult X 的远程重写和规则订阅，是我换设备、帮朋友配代理时最常翻的东西。但它们散在源站的不同页面，每次都要登录、找分类、复制链接、再手动拉起客户端导入——多台设备、不同客户端之间来回切，琐碎又容易漏。于是我做了 ClashModule：一个纯静态的浏览器索引页，把这些模块收拢到一起，以「导入 Clash」为主按钮、Loon / Quantumult X 为辅，搜索、筛选、一键拉起对应客户端导入，数据实时跟着源站走。

本文要点

  • 596 个模块：275 个 Loon 模块 + 321 个 Quantumult X 重写 / 规则合集，一次性收进一个索引
  • 一键导入 Clash 为主：主按钮即「导入 Clash」(hako://)，点一下拉起客户端；Loon（loon://）、Quantumult X（quantumult-x://）作为同场景备用，按需切换
  • 不止一键：每个模块都提供「复制链接」，可手动粘贴到任意客户端导入
  • 搜索 + 标签筛选 + 分页，移动端同样好用，自带暗色模式

它到底解决了什么

源站的模块是真的多，但访问路径是真的碎。要一个一个分类翻、复制安装链接，再切到客户端里粘贴，中间还隔着登录态和不同的页面结构。更麻烦的是分享——你拿着一套配置想发给用不同客户端的朋友，得先分清哪些是 Loon 模块、哪些要转成 Quantumult X 的 rewrite_remote / filter_remote，手误就导入失败。

ClashModule 把这件事压成一步：打开索引页 → 搜到 / 筛出想要的模块 → 点一下「导入 Clash / 导入 Loon / 导入 Quantumult X」→ 客户端自动弹起请求。源站更新了，页面数据也跟着更新，不用再各翻各的。

三种客户端的导入协议

不同客户端的「深链导入」协议不一样，页面按当前模块类型和你的客户端分别拼好：

  • Clash：用 hako://install-module?url= 拉起 hako 导入，主按钮文案即「导入 Clash」（协议本身不变）。
  • Loon：用 loon://import 直接把模块推给 Loon 导入。
  • Quantumult X：用 quantumult-x:///add-resource?remote-resource=<编码后的 JSON> 注入。页面会帮我把 rewrite 改写成 rewrite_remote、rule 改写成 filter_remote 再做 URL 编码，免去手动转换的坑。

如果当下不方便直接拉起客户端（比如桌面浏览器打开、手机没装对应 App），每个模块都带了「复制链接」按钮——复制出来的就是上面那串深链，你贴到能处理它的客户端里一样导入。

怎么用

  1. 打开 ClashModule 索引页，在搜索框输入关键词，或点来源 / 标签 chip 做筛选。
  2. 翻到目标模块，点最醒目的「导入 Clash」主按钮即可拉起客户端；若你用 Loon / Quantumult X，页面会按模块类型给出对应的导入按钮。
  3. 客户端弹起导入请求后确认即可；没弹起就点「复制链接」手动粘贴。
  4. 换设备时重复第 1–3 步，数据始终与源站保持一致，不用重新记分类路径。

一些顺手做的细节

  • 实时同步源站：页面内联一份快照实现秒开，再按缓存策略判断是否回源拉最新数据，既快又不失真。
  • 苹果风 UI：系统字体栈、毛玻璃卡片、大圆角、SF 蓝主色，并内置暗色模式（跟随系统或手动切换）。
  • 移动端友好：无横向滚动条，顶部工具栏在滚动时自动收起、回到顶部再展开，不遮挡内容。
  • 分页浏览：翻页后定位到第一排卡片而非页面顶部，长列表浏览不跳来跳去。
  • 页脚友情推荐：放了一个机场的推荐入口，需要的话顺手可取，不要也无妨。
