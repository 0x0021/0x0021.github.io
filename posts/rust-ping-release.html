rust-ping：一个用 Rust 重写的 ping，和三个只在真机上才露出来的坑

Rust ICMP 跨平台 踩坑记录 GitHub Actions

想有一个顺手的 ping：命令行能调次数、间隔、超时、载荷，也能写进配置文件；输出要么朴素、要么带颜色、要么是表格；Windows、macOS、Linux 都能直接跑。系统自带的 ping 各家参数不一样，脚本里也不好统一，索性自己写一个。rust-ping 就是这么来的——一个纯 Rust 的 ICMP Echo 工具，现在到 v0.1.3，CI 自动发 5 平台二进制，还有 deb、rpm、universal pkg 和 MSI 原生安装包。

本文要点

  • 7 个模块：参数、配置、ICMP 报文与收发、ping 主循环、统计、输出、入口；配置优先级为命令行 > TOML > 内置默认值
  • Broken pipe 不是权限问题：connect() + send() 在 TUN 路由下会被内核以 EPIPE 拒绝，sudo 也救不了，换成 sendto() 就好了
  • macOS 的 DGRAM ICMP socket 返回带完整 IP 头的报文，还会改写 identifier——解析要跳过 IP 头，匹配要以序号为准
  • msghdr.msg_controllen 在 Linux 是 usize、macOS 是 u32，本机编译通过不代表 CI 能过
  • 打 v* tag 自动交叉编译 5 平台、生成 SHA256、发布 GitHub Release

先把盘子搭起来

结构按职责切：命令行参数用 clap 定义成全是 Option 的字段，这样才能区分「用户没传」和「用户显式传了默认值」——否则配置文件里的值永远会被命令行默认值盖掉。配置文件用 serde + toml 读，合并顺序是内置默认值 → 配置文件 → 命令行。输出做成 trait，普通文本、颜色高亮、表格各实现一个，颜色开关独立控制，这样 --style color --color never 这种组合也不会打架。

ICMP 这块自己构造报文：类型 8 / 0（v4）和 128 / 129（v6），手写 RFC 1071 校验和，v6 还要加伪首部。TTL 通过 recvmsg 的控制消息拿，拿不到就从 IP 头读，再不行回退到发送值。socket 优先用 DGRAM 型 ICMP——Linux 和 macOS 上不需要 root，内核不支持再回退 RAW 并给出提权提示。

坑一：sudo 也救不了的 Broken pipe

第一版在本机跑 127.0.0.1 一切正常，一跑外部目标就全挂：

PING jd.com (198.18.4.221): 56 data bytes
warning: 第 1 包发送失败: 发送 ICMP Echo 请求失败: Broken pipe (os error 32)
...
4 packets transmitted, 0 received, 100.0% packet loss

第一反应是权限，sudo 跑了一遍——一模一样。那就是别的原因。查下来 198.18.4.221 是 Clash 的 fake-ip（198.18.0.0/15 是基准测试保留段），走 utun5 虚拟网卡；但系统 ping jd.com 却能通，说明 fake-ip 本身不是障碍。

为了排除干扰，我又拿真实内网地址 10.0.6.10 试：我的工具照样 Broken pipe，系统 ping 照样 0% 丢包。到这一步就很清楚了——不是地址的问题，是我的调用方式的问题。我创建 socket 后调用了 connect()，然后每轮用 send() 发包；在经 utun 路由的地址上，这个组合会被内核直接以 EPIPE 拒绝。系统 ping 用的是 sendto() 直接带上目标地址。把 connect() 去掉、改成 send_to(&packet, &target_addr)，IPv4 外部地址、fake-ip 域名、内网 IP 一次性全通。

这件事的教训挺朴素：看到系统错误先别急着归到权限。EPIPE 在这里说的是连接语义不成立，不是「你没资格发包」。

坑二：macOS 把 IP 头一起塞给你

改完 sendto 顺手测 IPv6，::1 又是 100% 丢包。开详细日志看原始字节，收到的是 80 00 ... 和 81 00 ...——分别是 Echo Request 和 Echo Reply。两个问题叠在一起：

  • macOS 的 DGRAM ICMP socket 会把完整 IP 头一起返回（Linux 通常不含），我从偏移 0 开始读 ICMP 头，类型、序号全错位。现在按首字节版本字段加协议字段识别并跳过 IP 头，顺带从 IP 头把 TTL 读了出来。
  • 本地 socket 会先收到自己发出去的 Echo Request。旧代码把「不是 Echo Reply 的包」返回成「超时」，主循环直接 break，真正的 Reply 晚一步到反而被忽略。现在接收结果分成 Reply / Ignored / Timeout 三态：非回复包继续等，只有真超时才收尾。

另外 macOS 会改写 ICMP 的 identifier，所以回复匹配以序号为准，identifier 只打进 debug 日志。这点在系统 ping 的实现里也是类似处理。

坑三：本机绿了，Linux CI 编译不过

流水线搭好后第一次跑就红在 clippy：本地 Rust 1.100 报 chunks_exact_to_as_chunks，那是新版本 lint，为了守住 1.70+ 兼容我加了 #[allow] 而不是改用 as_chunks。修完再跑，又红在编译：

error[E0308]: mismatched types
  --> src/icmp.rs:291
   |
291| msg.msg_controllen = control.len() as libc::socklen_t;
   |                     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ expected usize, found u32

根因是 libc::msghdr.msg_controllen 的类型按平台不同：Linux 上是 usize，macOS / BSD 上是 socklen_t（u32）。我在 macOS 上写死了 as libc::socklen_t，本机一直编译通过，到了 Linux runner 就炸。改成 as _ 让编译器按目标平台推断，才算真正跨平台。

这也是我坚持把 CI 跑起来的原因：「我机器上能过」不等于「能跨平台编译」，尤其是在直接调 libc 的地方。

流水线：打 tag 就发版

两条工作流。CI 在每次 push / PR 到 master 时跑格式化检查、clippy（-D warnings）、测试和 release 构建。Release 在推送 v* tag 或手动触发时，用矩阵并行编译 5 个目标：

  • x86_64-unknown-linux-gnu / aarch64-unknown-linux-gnu
  • x86_64-apple-darwin / aarch64-apple-darwin
  • x86_64-pc-windows-msvc

每个目标打包成 tar.gz（Windows 是 zip），附上 SHA256 校验文件，最后汇总发布 GitHub Release，release notes 自动生成。首版 v0.1.0 已经跑通，10 个资产全部到位。以后发版就是 git tag v0.2.0 && git push origin v0.2.0。

怎么用

# 装好之后
rust-ping 1.1.1.1 -c 5 -i 0.5
rust-ping jd.com --style table
rust-ping 8.8.8.8 --continuous

# 配置文件优先级低于命令行
rust-ping --config ./rust-ping.toml

配置能设目标、次数、间隔、超时、载荷大小、TTL、日志级别、输出样式和颜色开关；没传 --config 时会依次找当前目录的 rust-ping.toml 和 ~/.config/rust-ping/config.toml。仓库里放了 config.example.toml，也能用 --print-config 直接生成一份。
